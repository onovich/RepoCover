关于

我知道很多程序员并不擅长包装自己的仓库，我自己也一样：喜欢埋头苦干。

在 vibe coding 大行其道的今天，我开始意识到，让走过路过的人愿意多看一眼，或许有意义。

于是，就有了 RepoCover。我花了一天时间做的，看上去还不赖，我自己先用了。

先判断材料

截图是依据，但不应该直接等于设计。

RepoCover 会先判断仓库已有素材的美观度和代表性。好的部分保留并重组，干扰性的 UI 删掉，缺失的结构只在证据允许的范围内补充。

A

已有产品界面

保留有辨识度的真实界面，围绕核心交互裁切，同时清理浏览器边框、调试信息与画面碎片。

B

已有品牌或主形象

保留项目原有的角色、维度、配色和视觉作用，再重新组织周围的版式与信息。

C

没有可用图片

从项目真实的对象、动作、关系和结果中推导视觉系统，不假设之前已经存在一张好封面。

工作方式

先读，再画。

01

查看项目

阅读 README、关键代码、项目规则、截图和仓库自带的视觉素材。

02

前置诊断

确定一个核心承诺、仓库能支持的证据，以及不应该出现在封面里的内容。

03

重新构图

选择最能保留项目身份的制作方式，清理冗余并修正画面结构。

04

双尺寸验收

检查 SVG 和 PNG 的原尺寸与 320×160 缩略图，以及明暗两种背景。

常见问题

简单说。

没有截图也能生成吗？

可以。RepoCover 会从仓库证据推导视觉方向，但不会虚构运行结果，也不会假装看到了并不存在的界面。

能利用已有 Web 项目吗？

可以。能访问的本地预览或已有前端通常效果最好，因为可以检查真实界面，再有选择地重组。

每张封面会不会都很像？

不会。输出规格与验收标准一致，但配色、主体、维度、版式和材料会跟随当前项目。

会自动上传到 GitHub 吗？

只有你另外要求时才会。生成文件和修改仓库设置，是两次不同的授权。
