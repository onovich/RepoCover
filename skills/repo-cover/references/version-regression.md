# Version regression and promotion

Use this route only when an existing cover or retained candidate exists. A first-time cold-start generation must not depend on a previous cover.

## Preservation contract

Before drawing, record:

- **Identity anchors:** subjects, camera, dimensionality, materials, lighting, palette, topology, characters, or UI language that make the project recognizable.
- **Protected strengths:** what the current preferred cover already does well.
- **Allowed changes:** named composition, hierarchy, crop, copy, clutter, or evidence problems the candidate may fix.
- **Forbidden changes:** visual-medium shifts, invented relationships, generic restyling, or loss of proof.

Compare the strongest repository source, every retained cover, and the current preferred version. Do not treat the newest file as the baseline automatically.

## Version safely

- Create a versioned sibling; never overwrite the baseline merely because iteration was requested.
- Keep previous covers selectable until the user authorizes cleanup.
- Record evidence, treatment, material, line, fragment, and output paths per version.
- Generate a batch contact sheet when more than one repository is involved.

## Review without regression

Inspect source, preferred baseline, and candidate side by side at full size and `320×160` on light and dark surroundings.

Score the candidate against a zero baseline on:

1. identity fidelity;
2. product clarity;
3. aesthetic authorship;
4. abstraction fit;
5. topology fidelity;
6. material quality;
7. composition;
8. thumbnail legibility;
9. line semantics;
10. fragment integrity.

Treat these as veto dimensions:

- **Identity and dimensionality:** do not change medium, character, camera, material, lighting, or spatial logic.
- **Fragment integrity:** reject cropped text, partial UI, orphaned frames, duplicated interface content, or ambiguous seams.
- **Abstraction fit:** reject a more literal but more ordinary interpretation.
- **Topology fidelity:** reject flattened branches or overlapped independent states.
- **Material quality:** reject harsher contrast, lost meaningful texture or grid, or generic preset surfaces.

The candidate must fix at least one named weakness without lowering a veto dimension. Novelty alone is not improvement; ties retain the older default.

## Decide after inspection

Record one verdict with a plain-language reason:

- `promote`: candidate is measurably clearer or more faithful and passes all vetoes;
- `retain-baseline`: candidate is tied, different without net gain, or weaker in a nonfatal way;
- `reject`: candidate contains a known defect and should not be offered as a viable version.

Never derive verdicts from repository-name allowlists, generation branches, or decisions written before visual inspection. Open full-size outputs, thumbnail sheets, and the contact sheet first.

When the user accepts the latest selected version for each repository, record that selection as the next regression baseline while retaining older versions for reversible comparison.

For batches, inspect repeated left-card/right-screenshot splits, identical gradients, ornamental curves, generic glass panels, and shared diagram grammar. Diversity should emerge from repository evidence, not arbitrary decoration.
